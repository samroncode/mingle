# Plans

One file per larger change, named after the task (for example `quiz-module.md`). A plan is written before building, approved by the repo owner in chat or on the PR, and then kept as a record of what was intended.

Suggested sections:

- **Goal:** what the change should achieve, in one or two sentences.
- **Approach:** how it will be built, and which parts of the codebase it touches.
- **Steps:** the order of work, small enough that each step can be checked.
- **Open questions:** anything the owner needs to decide before or during the work.
